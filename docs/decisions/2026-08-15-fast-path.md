# Fast Path — `/dev:fix` becomes the fast lane

*Date: 2026-08-15 · Cycle: fast-path · Tier: standard · PR: [#79](https://github.com/awilliamsbuilds/claude-plugins/pull/79)*
*Handed off to autopilot at spec*

## Context

`/dev`'s seven stages are correctly weighted for a feature like `backlog-viewer` — hours of spec,
three validate loops, a decision log — and absurdly heavy for a one-line frontmatter fix.

`dev:autopilot` did not close that gap. It removes the **gates**, not the **ceremony**: a micro cycle
run unattended still creates a worktree, writes `spec.md` and `state.json`, dispatches two
challengers, runs a validate fix loop, writes `validation.md`, generates a decision log, and runs a
retrospective. For a typo that is the wrong trade in both directions — slow, and the artifacts it
produces are not worth reading.

The worked example was the session that produced the spec: six PRs merged in one sitting with zero
`/dev` artifacts, where rigor came from grounding before acting, running the suite, verifying in a
browser where the suite could not reach, capturing deferred work, and reporting honestly.

## Decision

**Build the lane, and the rule that refuses it.**

`/dev:fix "<what you want done>"` runs unattended through ground → triage → branch → change →
verify → PR, then stops. `/dev:fix merge` is a deliberate second invocation. Nothing irreversible
happens without it.

**Rigor is carried by judgment, not paperwork.** The lane may never skip a five-item floor — ground
before acting, run the suite when one exists, never claim unverified success, capture deferred work,
report what was decided on your behalf — and says in the PR body which applied.

**Escalation is keyed to unresolved decisions, not size.** Zero decisions proceeds regardless of
size; one is asked inline; two or more stops and prints the `/dev` command. A decision counts only if
the request doesn't determine it, no repo convention determines it, and reversing it would mean
re-editing the same files. A choice settled by convention counts as **zero** — that is precisely what
lets a mechanical 14-file rename through while a one-file change with two defensible answers stops.

**Today's `dev:fix` becomes `/dev:linear`.** The name describes what it does; `/dev:fix` is the
scarce good name and goes to the common case. Linear support retained.

## Consequences

**Enables:** Milestone 2 (`fast-path-backlog`, an entry adapter onto this lane) and Milestone 3
(`retire-legacy-commands`, which could not decide what to retire until the replacement existed).

**Forecloses nothing in the seven-stage pipeline.** `shape`, `build`, and `autopilot` are
byte-identical; every other stage skill carries only rename references plus three one-line
duplication pointers.

**Accepts a real duplication.** Every `/dev` stage gates on the prior stage's artifact
(`pr/SKILL.md:36`, `done/SKILL.md:45`, `validate/SKILL.md:40`, `build/SKILL.md:42`), so a lane that
writes no artifacts cannot enter the chain anywhere. It therefore mirrors `dev:pr` Step 4 and
`dev:done` Step 2/7. The duplication is named at **both** ends — in the lane and in the two canonical
steps — so an edit to one is not silently missed at the other. Extracting a shared reference is a
later cycle.

**Requires** `/plugin update` before the lane is live: the installed plugin is a snapshot of `main`.

## What review caught

Zero P1s in the original implementation. Five rounds — parallel code + security review, three fix
loops, an extended auto-fix pass, and a final confirmation — ended at 0 P1 · 0 P2.

The two that mattered most were both in the PR-opening path, and both were caught only because each
fix loop was cold-reviewed **against its own diff** rather than self-assessed:

- **Command injection.** The PR body carries the user's free-text request, verbatim test output, and
  quoted repo file content, interpolated into a double-quoted `--body` where `$…`, backticks, and
  `$(…)` still expand. This repo's own files are dense with `$WORKDIR` and `$(git rev-parse …)`, so
  silent variable loss was near-certain and a backticked payload reachable — unattended, so nobody
  sees the command first. Fixed to `--body-file`. The **next** review caught that `--title` still
  carried the same input in double quotes: an incomplete fix that read as complete.
- **Missing `--repo`.** `gh` resolves a fork's base repo to the fork's *parent*, so the lane run in
  anyone's fork would open a PR against an upstream they don't own.

A third — an infinite loop where the preflight would STOP while offering `/dev:fix merge` as its own
exit — was caught at Plan, before any code existed.

## Known-wrong, deliberately not fixed here

§P9's slug allowlist is documented in `references/tech-debt.md:354` and `reflect/SKILL.md:205` as
rejecting a leading `-`, "an argument-injection vector into the `gh --repo` invocation." It does not:
`-` is inside the character class, so `-foo/bar` passes. `dev:fix` anchors the first character in its
own copy and says why; the shared contract is untouched because `dev:debt`, `dev:done`, and
`dev:reflect` all read it, making that a scope decision rather than an edit. Tracked as
`debt-p9-slug-regex-allows-leading-dash`, with two smaller follow-ups on the merge tail.

## Retrospective

*Cycle: ~167 min wall clock · handed off to autopilot at Spec · 6 spec questions, 0 spec revisions*

### Where the time went

| Stage | Duration | Budget used |
|---|---|---|
| Spec | 43 min | challenger 2/3 loops |
| Plan | 3 min | challenger 2/3 loops |
| Build | 5 min | — |
| **Validate** | **95 min** | **3/3 loops + extended pass + 1** |

Validate was 57% of the cycle and the only stage to exhaust its budget. Both challengers finished
comfortably. Build took five minutes because Plan had already resolved the hard parts.

### The finding that justifies the whole design

**Three of the five Validate rounds were spent fixing my own fixes.** The cycle's only P1 did not
exist in the original build — it was created by an *incomplete* fix in loop 1: `--body` was moved to
`--body-file` while `--title` was left carrying the identical untrusted input. Loop 2's fix
(`--merged "$DEFAULT_BRANCH"`) introduced a stale-local-ref bug. Loop 3's `BRANCH = DEFAULT_BRANCH`
guard made a legitimately-interrupted tail unrecoverable.

Every one was caught by cold-reviewing **the fix diff itself**, not the original. A fixer re-reading
their own fix sees the intent they had; a reviewer seeing only the diff sees what landed. `dev:validate`
Step 4's per-loop cold re-review paid for itself three times in one cycle, and the argument generalizes:
the more confident the fix, the more it needs a reader who wasn't there.

### Process changes made

**Concerns are now foldable (PR #80).** Both challengers said concerns were "passed through, never
revised"; this cycle folded ~10 in, because a mechanical concern left unfixed resurfaces at Validate at
the cost of a full loop. The practice is now the documented rule, with the bound that matters kept
intact — a concern may be fixed inside a running iteration, never extend one. The counter semantics are
stated too: `applied` means "fixes the challenger caused," so this cycle's `applied: 11 / blockers: 0`
reads as the system working rather than as alarm.

**Stopping at the loop limit was confirmed correct.** Autopilot exhausted its Validate budget, stopped,
and surfaced state rather than grinding on unattended. That cost one user turn and was the right trade —
the alternative is an agent spending unbounded loops on a diff already at 0 P1.

### Signals for next time

- **`spec_revisions: 0` is accurate but uninformative on a handed-off cycle.** With no human at the gate,
  the metric cannot distinguish "the spec was solid" from "nobody was looking." Reading it as a quality
  signal on an autopilot cycle would be a mistake.
- **Validate's budget is the one that binds.** Spec and Plan challengers exited at 2/3 on a cycle this
  size; Validate needed 3/3 plus two more passes. If a tier's loop counts are ever retuned, that asymmetry
  is the evidence.
- **The user reported no observations of their own** — the automated review surfaced everything either
  side had. Worth noting rather than omitting: it is weak evidence the cold-review nets are catching what
  a human review would, on a cycle where the human deliberately stepped back at Spec.
